# Refine KLAIM landing-page messaging

## Scope
Preserve the current dark visual system, responsive layout, hero capsule, typography, spacing, and animations. Update only landing-page content and the existing diagrams/components needed to tell the final product story.

## Changes
- Refine hero and site-wide positioning so KLAIM clearly verifies human identity claims for AI-agent requesters using privacy-preserving proofs and per-request x402 payments.
- Enhance the existing proof capsule labels with the concrete verified claim and technical stack while keeping the 3D composition intact.
- Update the problem cards around excessive PII, fragmented verification, and the lack of an agent-native verification/payment interface.
- Replace the current two-column concept flow with a clear relationship diagram: human consent and trusted credential enter KLAIM; the AI agent requests through MCP and pays through x402; only a verified claim returns.
- Expand the existing payment flow and terminal example to show MCP, HTTP 402, USDC on Algorand Testnet, ZK proof generation, claim output, privacy status, and transaction receipt.
- Strengthen the existing privacy comparison so traditional document sharing is contrasted with consent → credential → ZK proof → verified claim, explicitly marking DOB and documents as not disclosed.
- Update the MCP console copy and outcome to show an agent verifying a human customer, with no DOB disclosed.
- Add a compact five-step “How KLAIM works” sequence and refine the technology/use-case content, including trusted credentials as the identity source.
- Add a focused “Why KLAIM?” four-point band using the existing card language, with Privacy-first and Pay-per-use emphasized.
- Refine the final CTA, footer description, and page metadata to match the human-verification positioning.

## Validation
- Check the generated page at desktop and the current narrow viewport for overflow, overlap, and text fit.
- Confirm the project build remains clean and no copy suggests that KLAIM verifies AI agents or stores raw credentials.
